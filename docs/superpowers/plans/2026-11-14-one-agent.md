# One Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Execute inline; the owner prohibits subagents.

**Goal:** Use one agent for chat, forwarded email, pasted email and follow-ups, with retained source access and explicit item confirmation.

**Architecture:** Persist accepted agent turns and process them serially through one context builder, instruction set and tool loop. Source preparation remains mechanical. The agent returns an outcome; one transaction publishes its text, proposals or review patch and completes the turn, preventing duplicate writes after restart.

**Tech Stack:** Existing Go services, SQLite, OpenRouter, Flutter and pinned toolchain; no new external service.

**Spec:** [One agent design](../specs/2026-11-14-one-agent-design.md).

## Global Constraints

- One instruction set and agent execution loop; remove the extraction-only model path.
- Forwarded MIME, source text and attachments remain untrusted data. Only owner requests authorize changes; Confirm remains explicit.
- Retain existing source conversion limits and the 400,000-byte textual source budget. No content keyword routers, duration parsers, new call caps or private fixtures.
- Preserve current items, review states, usage and push registrations. No production reset or replay of the owner's email.
- Work inline on guided-email-review; do not merge main. Deploy tested code and serve the APK over the existing LAN server.
- Follow the applicable AGENTS.md chain before edits; update contracts with behavior changes.

## Review Focus

- A conversational question while a duration question is open must be answered without superseding its candidate (Task 3).
- A source arriving during chat or just before shutdown must remain queued and resume without duplicate previews (Tasks 1 and 4).
- A retained source outside the recent-history window must remain discoverable, and deletion must revoke access (Task 2).
- A plausible but unsupported duration must never be defended as a source fact; test with the real model on synthetic material (Tasks 3 and 4).
- A long pasted email must reach the agent intact, including multibyte text, without bypassing request byte limits (Tasks 1 and 4).

### Task 1: Durable serialized agent turns

**Files:**
- Create: server/domain/agent.go, server/port/agent.go, server/store/agent.go, server/store/migrations/006_agent_turns.sql, server/store/agent_test.go.
- Modify: server/port/persistence.go, server/conversation/service.go, server/conversation/service_test.go and owning AGENTS.md files.

**Interfaces:**
- domain.AgentTurn: ID, Kind (owner, source_arrival, review_reply), EntryID, SourceID, CandidateID, ExpectedRevision, State, CreatedAt, LeaseUntil and Error. Text stays on its retained entry/source, not duplicated in turn metadata.
- port.AgentTurns adds AgentTurn(id string) (domain.AgentTurn, error) and PutAgentTurn(domain.AgentTurn) error to port.Transaction.
- store.EnqueueAgentTurn(turn domain.AgentTurn, entry *domain.Entry) (domain.AgentTurn, error) atomically stores the optional owner entry and pending turn; a repeated turn ID returns the existing record.
- store.ClaimAgentTurn(now time.Time) (domain.AgentTurn, error) claims the oldest queued turn only when there is no unexpired active lease. One process and concurrent workers must obey the same serialization invariant.
- conversation.Service.Accept keeps its Accepted response shape. Accepted owner input is durable before HTTP success. Existing busy rejection may remain for a second owner submission; incoming sources queue independently.
- conversation.Service.EnqueueSource(sourceID string, revision int) error uses a deterministic arrival identity. The worker is canceled and joined by Close; a lease abandoned on shutdown can resume on restart.
- Completion/failure uses the transaction interface so final writes and turn state are atomic. The result application implementation belongs to Task 3.

**Interfaces:**
- domain.SourceRef: ID, Kind (email, chat), EntryID, CaptureID, Label, CreatedAt and Deleted. Payloads are loaded by reference rather than copied into every turn.
- domain.SourceDocument: Source domain.SourceRef, Document domain.CaptureDocument. Reuse parsed parts/coverage and raw file storage; domain types do not import adapters.
- port.Sources adds Source(id string) (domain.SourceRef, error) and PutSource(domain.SourceRef) error to port.Transaction.
- store.FindSources(query string) ([]domain.SourceRef, error) finds retained sources by subject/label, sender or retained chat text. Deleted sources are excluded. Oversized tool results ask for a narrower query instead of silently dropping matches.
- capture.Service.ReadSource(ctx context.Context, id string) (domain.SourceDocument, error) resolves email originals through the existing parser/files; chat sources load the retained entry as a text part. It checks deletion on every read. This method performs no extraction, model call, push or item change.
- capture.Service.FindSources(ctx context.Context, query string) ([]domain.SourceRef, error) delegates the store query. Expose the two methods to the agent through its own small SourceReader interface, wired in main.
- Source preparation creates the source reference and queues its arrival exactly once. Retained owner entries are discoverable as chat sources; tool publication of a review persists the source reference when needed. Reuse existing capture review records for chat sources with an explicit source kind and entry reference.

### Task 3: One context, instruction set, tool loop and review updates

**Files:**
- Create: server/assistant/turn.go, server/assistant/sources.go, server/assistant/turn_test.go, server/assistant/sources_test.go, server/domain/review_patch.go, server/command/agent.go, server/command/agent_test.go.
- Modify: server/assistant/assistant.go, prompt.go, capture.go, model.go and their tests; server/openrouter/client.go and tests; server/review helpers; server/capture/review.go and worker.go; server/cmd/minder/main.go; applicable contracts.

**Interfaces:**
- assistant.Service.Run(ctx context.Context, turn domain.AgentTurn) (domain.AgentOutcome, error) is the single model execution entry. It builds current owner history, source/review references and item context, then executes the common tools. Legacy Reply becomes a compatibility wrapper only during migration and is removed when callers move.
- domain.AgentOutcome: TurnID, Text, Proposals []domain.Proposal, Review *domain.ReviewPatch, Offer *domain.Offer and CostEUR. Represent existing list/read-only results in Text. The outcome is not persisted until command.CommitAgentTurn.
- domain.ReviewPatch: SourceID, ExpectedRevision, Summary, Notification, Candidates []domain.CaptureCandidate. For an existing review, Candidates contains only explicit updates/new candidates. Omitted candidates remain unchanged; confirmed/discarded candidates cannot be overwritten. New candidates get server IDs if absent; updates require an existing ID and matching revision.
- command.Service.CommitAgentTurn(turn domain.AgentTurn, outcome domain.AgentOutcome) ([]domain.Entry, error) atomically applies validated proposals/review changes, posts response entries, records cost on the first entry and marks the turn complete. Repeating a completed turn returns its prior entries. No item is confirmed by this method.
- command.Service.FailAgentTurn(turn domain.AgentTurn, cause error) error posts one visible failure per turn and marks failure atomically. Source-arrival failures retain their capture failure notification behavior; ordinary owner answers do not queue review pushes.
- Common tools include find_sources(query), read_source(source_id), inspect_review(source_id), propose_review(source_id, expected_revision, candidates, summary, notification) and the existing item/profile/list/approved lookup tools.
- Read tools return data to the same agent loop with tool-call identity. Extend assistant.Message/OpenRouter serialization for tool requests/results instead of inventing owner instructions. Account for every model call; cancellation/request budgets terminate with a visible failure, not an arbitrary new call cap.
- Both ordinary typed messages and AnswerCandidate quick replies enqueue agent turns. A quick reply carries source/candidate/revision context but does not supersede a candidate before the agent interprets it.

- [ ] Write a recording-model regression: identical actionable source supplied by arrival or paste uses the same system instructions/tools and produces the same four-candidate review. Assert there is no PurposeEmail or extract_capture-only request.
- [ ] Write multi-turn read-tool tests for source-based follow-ups, images, old sources, deletion, ambiguous references, and external prompt injection. The source must arrive as untrusted data; the owner's question remains the instruction.
- [ ] Test a question during an open duration prompt leaves candidates unchanged. Test a targeted answer updates only its candidate and preserves all four candidates plus the first confirmed item. Reject stale revisions and attempted terminal-candidate writes without partial changes.
- [ ] Test result commit idempotency, rollback after a deliberately failed preview, costs across read/model calls, no extra read push, and once-only source review/failure pushes.
- [ ] Run `toolchain/run go go test ./assistant ./openrouter ./command ./capture ./conversation`; observe the new behavior fail before implementing it.
- [ ] Implement common instructions, tools, loop and transactional publication. Explicitly distinguish source facts, owner answers and assumptions; a pending record does not prove source support. Missing duration asks the owner and leaves end/duration empty. Keep quote validation as a mechanical check.
- [ ] Wire all turn producers to the shared worker, remove the separate extraction persona and its correction/re-extraction path, and migrate old unit fixtures to the common tool contract rather than retaining a hidden legacy mode.

## Execution ledger

Tasks 1 to 4 are implemented inline on `guided-email-review` and verified locally ([evidence](../../evidence/one-agent.md)). Rulings: the code-side duplicate-booking check was dropped in favour of the prompt; evidence problems return to the model as tool results instead of a correction call; arrival turns are queued in the preparation transaction, so `conversation.EnqueueSource` was not added; a revision bump happens only when a patch updates a candidate; `AgentTurn.EntryIDs` and `SourceRef.Sender` were added; `Capture.Prepared` stops a prepared source being claimed again. Not done: production deployment (needs the owner's go-ahead because schema 6 is one-way for the old binary) and Telegram delivery.
